# Vidify MVP 产品与工程决策

**状态：** 已接受（MVP 行为基线）

本文记录 Vidify 的产品边界和工程决策，描述目标行为而非完整实现状态。首条转录、SRT、ASS 累积排版和 MP4 端到端切片已实现；当前进度和剩余工作见 [MVP 命令行契约](../cli-contract.md)。未决事项列在文末，讨论收敛后再形成实现规格。

## 产品方向

Vidify 是长期维护的个人 Go CLI 项目，MVP 面向维护者自己的音频转视频工作流。首要产物是 MP4 视频，字幕文本可以成为画面主体；工具不限定英语学习用途，也不把产品定义为波形可视化或整篇文章讲义。

MVP 一次处理一个本地音频文件，自动转录并在用户指定目录生成同名 MP4 和 SRT。首版不支持视频输入、批处理或媒体库。`videos/` 目录仅作未来规划，MVP 不启用。

正式支持 WAV、MP3、M4A（AAC/ALAC）。FFmpeg 负责解码并转换为 16 kHz、单声道、16-bit PCM WAV，供 whisper.cpp 转录。其他 FFmpeg 可解码格式允许尝试，但不承诺兼容。校验输入时不能只依赖扩展名；应确认文件中存在可解码的音频流。应为正式支持格式准备正常、损坏和缺少音频流的测试样本。

## 转录、字幕与视频呈现

MVP 只使用本地 whisper.cpp 作为语音识别后端。用户自行安装 FFmpeg、whisper.cpp 并提供兼容的本地模型；Vidify 不下载、安装、更新或打包这些外部依赖。模型路径由用户显式指定。转录语言默认自动检测，用户可通过参数指定语言；可用语言取决于模型。

Go 负责进程管理、任务编排、状态、日志、错误处理、转录数据校验和字幕排版。转录数据使用 Vidify 自己的 `Segment` 概念，包含开始时间、结束时间和文本。优先使用 whisper.cpp 的真实时间戳；验证时间戳顺序、区间合法性、空文本和异常输出。不按文本长度推算时间，不假设 whisper.cpp 能可靠识别说话人。

MVP 以句段级时间戳生成标准 SRT，排版以短语级可读性为目标。字幕内容、SRT 导出、页面排版和视频渲染保持分离。SRT 使用每个 Segment 原始的发声区间；MP4 中的文本页面按累积显示规则呈现，同一 Segment 的两种显示时长可以不同。

Vidify 使用 Go 生成临时 ASS 文件，由 FFmpeg/libass 渲染视频。Go 预先计算换行、页面、位置和显示时间；每个 Segment 生成一个 ASS 事件，从 Segment 的开始时间显示到当前页面结束，避免为每个更新状态重复输出整页快照。布局必须防止 libass 自动碰撞调整改变预期位置，并统一处理 ASS 时间精度、重叠和分页边界。

字幕页面按音频进度逐步累积文本。每个 Segment 在其开始时间显示完整文本，并持续显示到当前页结束。若下一个完整 Segment 放不进当前页，则在该 Segment 开始前切换到新页；新页从该 Segment 的开始时间显示，旧页同时结束。最后一页显示到音频结束。Segment 不跨页拆分。

页面容量根据文本在可用画面区域中的实际排版结果判断，不使用固定行数。新页上的单个 Segment 仍放不下时，只缩小该页字号，并设可读性下限；仍无法容纳时，在正式编码前返回明确错误，包含 Segment 编号、时间戳和原因。不得裁切、丢弃文本、随意拆句或制造伪精确时间戳。明显异常的转录片段应在排版前检查。

画面采用 16:9、1920×1080、恒定 30 fps。MVP 使用一种固定的内置视觉样式，参照维护者提供的截图；正文采用衬线字体并左对齐，不显示页码，标题暂不纳入 MVP。精确配色、字体参数和页面安全边距暂缓决定。当前切片暂时嵌入 DejaVu Serif 并将同一字体提供给 Go 排版和 libass；这只是度量与渲染一致的临时字体，最终字体和样式仍待决定。

MP4 使用 H.264 视频与 AAC 音频，并保留输入音频供播放。FFmpeg 构建必须具备 `ass`/libass 字幕渲染能力及所需编码器。处理前检查可执行文件、模型和必要滤镜/编码能力，并通过实际渲染检查确认配置可用。

## 任务、文件与可观测性

每次运行是一个进程内任务，不提供跨进程恢复、数据库、持久化状态机或批处理。任务阶段按线性顺序转换：检查依赖与输入 → 转换音频 → 转录 → 排版 → 渲染 → 发布；终态为成功、失败或取消。转换集中验证合法后继，禁止跳阶段和重复进入终态。任一执行阶段可进入失败或取消，并保留失败阶段与错误上下文。状态只表达主要阶段，不为内部子操作分别建模；清理不属于任务状态。

Go 标准库管理外部进程，不通过 Shell 拼接命令。可执行文件优先使用用户显式路径，否则从 PATH 查找。开始处理前尽早检查缺失、不可执行及明显配置错误，并用可操作的错误说明问题。日志默认输出终端、不创建永久日志文件；结构化记录任务 ID、阶段、依赖路径、可获取的版本、耗时和错误上下文。MVP 提供阶段级进度，不显示估算百分比。

用户按 Ctrl+C 时取消整个任务，停止并等待当前子进程退出，清理未发布的临时产物并以非零状态结束。已完成且有效的正式产物可以保留。成功必须满足 MP4 与 SRT 均已发布并验证。

应用临时工作区使用平台规范的用户缓存/应用数据目录，并允许用户自定义路径；`~/.vidify/` 仅是概念示例，不是固定路径。每个任务使用独立 UUID 目录 `tmp/<task-uuid>/`，所有普通中间文件集中在其中。`videos/` 预留但不启用。

最终输出放在用户指定目录，不强制进入 Vidify 内部媒体库。输入文件保持只读。默认拒绝覆盖已有产物；Vidify 自身的并发任务不得争用同一输出目录。MVP 使用目录级持久锁位置文件，并通过操作系统文件锁协调 Vidify 进程；文件存在不代表锁被持有，进程退出后操作系统释放锁，Vidify 不按 PID 或文件年龄接管，也不自动删除锁位置文件。Linux 使用 `flock`，Windows 使用 `LockFileEx`；这需要窄范围的平台实现。持锁期间重新检查目标并发布。锁已被持有时快速返回冲突错误，不排队。外部程序同时写入目标路径造成的竞争不在 MVP 保证范围内，也不承诺跨平台原子无覆盖。为避免跨文件系统复制大型 MP4，最终产物可在目标文件系统上暂存、验证后发布；这是普通中间文件集中在任务目录规则的明确例外。发布前验证 MP4 与 SRT；先发布 SRT，再发布 MP4。只有两者都成功发布，任务才进入成功终态。若 SRT 已发布而 MP4 发布失败，保留有效 SRT，返回失败并报告残留产物路径。MP4 是否存在只能辅助判断发布状态，不能单独证明任务成功。Vidify 只清理能够确认归属的任务临时目录。成功后清理临时文件；失败或取消时安全清理；`--keep-temp` 保留任务临时文件供调试。异常退出可能留下残留目录，MVP 不实现自动恢复或复杂缓存清理。

若 MP4 和 SRT 均已成功发布、验证，任务即为成功。之后临时文件清理失败时，退出码仍为 0，并记录 Warning，包含任务 ID、原因和残留路径；不回滚或删除正式产物。清理错误不能覆盖核心任务错误。不因清理失败改变成功状态。使用 `--keep-temp` 时保留文件是预期行为，不产生清理警告。

## MVP 明确不做

- 多语音识别后端或插件系统；未来只有在实际性能测试后才评估 faster-whisper。
- 自动下载、安装、更新或打包 FFmpeg、whisper.cpp 和模型。
- 批处理、跨进程任务恢复、持久化任务库或媒体库。
- 逐词时间戳、逐词高亮、打字机效果、动态波形、复杂模板。
- 自动说话人识别或说话人标签推断。
- 视频文件输入、标题编辑和多种画幅/样式配置。

## 仍待决定或验证

- 固定样式的具体色值、字体参数和页面安全边距。
- 正式使用的衬线字体文件及许可证记录（当前内置 DejaVu Serif 仅为临时值）。
- whisper.cpp 版本/构建的兼容范围，以及首批验证的模型变体。
- 用户自定义工作区路径的具体配置入口。
- 子进程 stderr 的默认输出、失败诊断截取与详细日志选项。
- 清理时点和各类失败/取消的数值退出码。任务状态目前由进程内线性阶段状态实现。
- ASS/libass、H.264/AAC 能力检查的具体方式；真实渲染和长音频性能需要在可运行切片中验证。
- 模型线程数、FFmpeg 质量参数及其他编码默认值。

以上未决事项未被本文写成已接受决策。实现前应通过代表性英语音频验证识别、分页、可读性、同步和跨平台渲染，并在具备依据后再调整规格。
